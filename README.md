# SSB

Linux CLI для сбора TCP/IPv4-обращений и резолва IP в имена хостов. Отчёт содержит входящие и исходящие связи, порты назначения и таблицы имён удалённых узлов по направлениям.

## Сборка и запуск

Для сборки нужен Go 1.22 или новее. Сторонних Go-модулей нет.

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -buildvcs=false -trimpath \
  -o network-inspect ./cmd/network-inspect
sudo ./network-inspect 120
```

На целевой ВМ нужны бинарник, `tcpdump` в `PATH` и права на захват пакетов. Go и интерпретаторы для запуска не нужны.

```bash
sudo ./network-inspect        # сбор 60 секунд
sudo ./network-inspect 120    # сбор 120 секунд
./network-inspect --help
```

Каждый запуск создаёт отдельный каталог `tcp-report-*` с правами `0700`. В нём сохраняются TXT-отчёт и `raw/` с выводом tcpdump, диагностикой, снимком адресов интерфейсов и неразобранными строками. Файлы имеют права `0600`. Отчёт также выводится в терминал. При ошибке захвата сохраняются исходные данные; Ctrl+C и SIGTERM останавливают запуск с ошибкой. JSON и схемы не создаются.

## Что наблюдается

Сборщик фиксирует TCP/IPv4 SYN без ACK — попытки подключения, включая неуспешные. Уже открытые соединения, UDP, IPv6, локальные обращения и транзит не включаются. Повторы с одинаковыми инициатором, получателем и портом назначения объединяются; порт инициатора не сохраняется.

IP и маски берутся из интерфейсов на старте. Собственные адреса `127.0.0.1` и весь диапазон `172.x.x.x` исключаются вместе со связями через них. Удалённые адреса `172.x.x.x` сохраняются, если свой конец связи допустим. Если подходящих адресов ВМ нет, запуск завершается до захвата. Неизвестные счётчики качества не подменяются нулём.

После захвата каждый уникальный IP разрешается через `/etc/hosts` и системные DNS-серверы: до 2 секунд на адрес и 15 секунд на весь этап. Найденные имена сохраняются при частичном результате; неизвестные обозначаются `-`. В группе «Входящие» выводятся удалённые клиенты, в группе «Исходящие» — удалённые получатели. Один IP может находиться в обеих группах, но не повторяется внутри группы.

Статическая сборка использует резолвер Go без дополнительных служб NSS, таких как LDAP или mDNS. Найденное имя узла может отличаться от домена, к которому обращалось приложение.

## Проверки и разработка

```bash
go test ./...
go vet ./...
python3 -m unittest discover -s tests -p test_publication.py
```

IP в тестах — условные данные. Разработка ведётся в `dev`; обычные PR направляются в `dev`, готовые изменения проходят PR `dev → main`.

Проверки, независимое ревью, правила публикации и откат описаны в [CONTRIBUTING.md](CONTRIBUTING.md). Критерии ревью — в [REVIEW.md](REVIEW.md).
