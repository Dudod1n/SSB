# SSB

Linux CLI с терминальным интерфейсом для наблюдения TCP SYN, UDP/IPv4 и установленных TCP-соединений. Он показывает адреса, порты, счётчики пакетов и имена узлов, сохраняет TXT и исходные данные в `raw/`.

## Сборка и запуск

Нужен Go 1.22 или новее; сторонних Go-модулей нет.

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -buildvcs=false -trimpath \
  -o ssb ./cmd/ssb
sudo ./ssb        # захват 60 секунд и TUI
sudo ./ssb 120    # захват 120 секунд и TUI
sudo ./ssb --plain 60
sudo ./ssb 60 > session.txt  # обычный текст без ANSI
./ssb --help
./ssb --version
```

На целевой ВМ нужны бинарник, `tcpdump` в `PATH` и права на захват пакетов. Go, интерпретаторы и `ss` для запуска не нужны. TUI включается, когда ввод и вывод подключены к терминалу, а `TERM` задан и отличается от `dumb`. Для него нужен UTF-8 терминал от 45×19, желательно 100×30, с поддержкой ANSI и TrueColor. `--plain` сохраняет обычный режим и в терминале.

## Терминальный интерфейс

В первой строке находятся версия SSB, IP и hostname. Поиск и детали выбранной строки расположены сверху, таблица занимает основную часть экрана, подсказки — в нижнем блоке «Навигация». Короткий прогресс появляется во время настоящего захвата. После завершения строка показывает фактическую длительность и текущий этап обработки. Неизменившиеся строки повторно не записываются в терминал.

| Клавиши | Действие |
| --- | --- |
| `1`, `2`, `3`, `4` | Все наблюдения, входящие пакеты, исходящие пакеты, открытые TCP |
| `Tab` | Следующий вид |
| `↑↓`, `j/k` | Выбрать строку |
| `/`, `Enter`, `Esc` | Ввести поиск, применить, очистить |
| `s` | Сортировать по порту или IP получателя |
| `r` | Начать новый захват после завершения предыдущего |
| `e` | Сохранить полный TXT в текущий каталог |
| `q`, `Ctrl+C` | Выйти и остановить незавершённый сбор |

Поиск учитывает IP, порты, имена, протокол и состояние. Во время ввода буквы `e`, `r` и `q` остаются текстом поиска. Повторный захват не запускается параллельно с текущим и создаёт отдельный каталог. Данные пакетов становятся доступны после захвата, имена — после поиска DNS; открытые TCP видны уже из начального снимка.

`e` доступна после готовности отчёта и сохраняет все наблюдения, независимо от поиска и выбранного вида. Каждый файл `ssb-report-*.txt` уникален и имеет права `0600`. Ошибки записи показываются на экране; при невозможности убрать неполный файл его имя сохраняется в сообщении. Сложные emoji-последовательности могут занимать разную ширину в разных терминалах.

## Сохранение и завершение

Каждый сбор создаёт отдельный каталог `tcp-report-*` с правами `0700`. Готовый TXT сохраняется автоматически; `e` создаёт дополнительную копию. Файлы имеют права `0600`. В `raw/` находятся краткий вывод `packets.log`, диагностика `capture.log`, адреса интерфейсов, неразобранные строки и снимки `tcp-before.txt`/`tcp-after.txt`, `tcp6-before.txt`/`tcp6-after.txt`. JSON и схемы не создаются.

В обычном режиме отчёт также выводится в stdout. В TUI после выхода показывается каталог результата. При ошибке и прерывании исходные данные сохраняются, но незавершённый сбор не выдаётся за готовый TXT. `q` штатно закрывает TUI; Ctrl+C и SIGTERM завершают его с кодами 130 и 143. В обычном режиме прерывание сохраняет исходные данные и завершается с ошибкой.

## Что наблюдается

Входящие и исходящие таблицы объединяют протокол, IP отправителя/получателя и порт назначения. «ПАКЕТЫ» считает SYN без ACK для TCP и разобранные UDP-пакеты; повторные наблюдения включаются в счётчик. Порты отправителей остаются в `raw/packets.log`. Повторный SYN может быть повторной передачей, а захват на нескольких интерфейсах может дать дубли. Счётчик не означает число успешных подключений. Краткий режим tcpdump не разбирает прикладные UDP-запросы, например DNS.

Установленные TCP-соединения, в том числе без трафика, берутся из `/proc/net/tcp` и IPv4-mapped записей `/proc/net/tcp6` до и после захвата. Они показаны отдельно: LOCAL и REMOTE с портами, имя удалённого узла и наличие в снимках. `+` означает наличие, `-` — отсутствие в полученном снимке, `?` — неполный или недоступный снимок. Его доступные строки сохраняются даже при ошибке другой таблицы. Направление и первоначальный инициатор для этих строк неизвестны. Одинаковые endpoints в двух снимках не доказывают непрерывность соединения; соединения, жившие только между снимками, могут отсутствовать в таблице ESTABLISHED.

Наблюдение ограничено IPv4 и текущим сетевым пространством имён. IPv6, локальные обращения и транзит не включаются. Собственные адреса `127.0.0.1` и весь диапазон `172.x.x.x` исключаются вместе со связями через них; удалённые `172.x.x.x` сохраняются при допустимом собственном адресе. Если подходящего IPv4 нет, запуск завершается до захвата. Периодические снимки и весь TCP-трафик не собираются. Неизвестные показатели качества не подменяются нулём.

IP и маски интерфейсов берутся на старте каждого сбора. После захвата имена ищутся через `/etc/hosts` и системные DNS-серверы: до 2 секунд на адрес и 15 секунд на весь этап. При частичном результате найденные имена сохраняются; неизвестные обозначаются `-`. Статическая сборка использует резолвер Go без дополнительных служб NSS, таких как LDAP или mDNS. Имя узла может отличаться от домена приложения.

## Проверки и разработка

```bash
go test ./...
go test -race ./...
go vet ./...
python3 -m unittest discover -s tests -p test_publication.py
```

Go-тесты проверяют разбор данных, приватные файлы, остановку процессов, реальный tcpdump на искусственном pcap без захвата интерфейсов и TUI через Linux PTY. Полный тест сборщика подменяет tcpdump и отключает внешние DNS-запросы; ему нужен доступ к метаданным интерфейсов. Недоступные возможности явно отмечаются как skipped. Адреса в исходных тестовых данных условные.

Разработка ведётся в `dev`; обычные PR направляются в `dev`, выпуск проходит PR `dev → main`. Порядок проверок, независимого ревью, публикации и отката описан в [CONTRIBUTING.md](CONTRIBUTING.md). Критерии ревью — в [REVIEW.md](REVIEW.md).
